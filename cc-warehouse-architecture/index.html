1st · C1 - Parse once: one parse product

PROPOSED Strong in-process

parser.py · render.py · build.py

flowchart LR
  A[raw bytes] --> B[parse_session]
  A --> C[build_conversation]
  B --> D[extract entries]
  C --> E[extract entries again]
  D --> F[metadata]
  E --> G[conversation model]

Problem. parser sells two products over the same bytes, each re-running the extraction (parser.py:158, :403). render's emitters take raw bytes, so one projection extracts the payload five times (render.py:375-377, 726-727, 740; build.py:84-86). DESIGN section 4 says parse ONCE; the interface defeats it.

Solution direction. One parse entry extracts once and yields metadata plus conversation together; emitters accept the parsed model, bytes kept only at the edge.

  • leverage - one parse, three emitters
  • locality - extraction quirks in one function
  • 5x parse cost gone before the large migrate and v1.1 FTS5
  • makes the DESIGN parse-ONCE sentence true (R8)

3rd · C3 - Make the risky transforms public and I/O-free

PROPOSED Strong in-process

share.py · relocate.py

Problem. The correctness-critical logic of the two riskiest verbs is pure transformation, yet private behind Config-plus-disk entry points: share's secret detectors and relocate's JSON-aware rewriter. Locality is lost, because a redaction miss lives in one function while the catching test runs three process boundaries away.

Solution direction. Public, I/O-free interfaces: decoded text in, hits out; text or JSON node plus mapping in, rewritten result out. Verbs keep the I/O shell.

State change 2026-07-24: the natural home closed without taking it.

Ticket 12b is DONE and its work landed squarely on this surface, but the seam was never folded into its work order as this card recommended. Verified first-hand: the rewriter helpers are all still private, and the surface GREW by two more. Share's half is unchanged.

The argument got stronger while nobody acted on it. 12b's headline defect was exactly the class this card predicts: an escaped path form was invisible to the scan, so a file was never a candidate and verify confirmed success over it. It is now pinned by tests/test_relocate_json_matrix.py, whose 29 cases must each run a full CLI subprocess because the transform underneath is not callable directly. That test file is this card's own evidence.

Re-rank recommendation: strongest un-built candidate on the board; move to 1st or 2nd at the next review. The timing objection that placed it 3rd is spent, because 12a, 12b and 13 have all landed.

4th · C4 - Give the head concept one home: a catalog read seam

PROPOSED Strong in-process

catalog.py · build.py · share.py · cli.py

Problem. "A head is a row no other row supersedes" has no owner: the predicate SQL is typed verbatim twice while a docstring claims one owner, an overclaim (R8/F6); a private shape is re-declared field-for-field in share; cli runs its own SELECTs; test helpers hardcode schema SQL.

Solution direction. catalog.py owns the head predicate, a public head-record type, and the read queries; build, share and cli consume them. Reads stay catalog-only, R6 unchanged.

  • locality - version-chain semantics beside the schema
  • leverage - v1.1 search and v1.2 MCP read the same seam
  • makes the docstring true (R8)
